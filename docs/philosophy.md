## 1. 它是什么

**dsh-taskbearing** 是 DSH（DeepSeek Harness）的**工作区级任务记忆与方向恢复插件**。它做四件事：

- **存**：把 AI 规划的任务树、每个节点的双线状态、详情、用户备注、追溯链按工作区存下来。
- **显**：右侧栏按视图展示任务清单，用户只看人话；点开详情才看给 AI 的干货。
- **提**：靠 DSH 全局规则文件让 AI 主动维护任务板（插件不做每轮注入）。
- **交**：一键复制交接内容，丢给新会话 AI 接手，不用重读历史。

它解决四个真实痛点：

| 痛点 | 表现 | 插件怎么解 |
|---|---|---|
| 方向感丢失 | 聊几十轮后忘了最初要什么、做到哪 | 需求树 + 双线状态 + 需求原话钉在基线里 |
| 状态不可读 | AI 写的进度满是函数名 | `human_line` 一句话人话 + 详情给 AI 看 |
| 切换会话断档 | 新会话接不上子步骤级进度 | 复制交接 + 新会话 AI 读板 |
| 事实靠记忆 | AI 编造文件路径、原话越写越走样 | 路径写入强校验 + 原话逐字比对 |

**它不是什么**：不是规则引擎、不是代码生成器、不是项目管理软件——**判断权归 AI，插件只做格式、完整性与事实性校验**。

## 2. 设计哲学

### 2.1 判断权归 AI，插件只存不判

插件**不判断**「做完没有 / 覆盖没有 / 是否冲突 / 值不值得拆」。它只回答两类问题：

- **格式对不对**：字段类型、枚举、层级不变量、状态转移是否合法；
- **事实真不真**：原话是否与会话逐字一致、详情里的文件路径是否真实存在。

判断「该不该标已执行」「这个改动是否影响原需求」永远是 AI 的事。

### 2.2 事实可核对，而不是“相信”

三个锚点保证事后可核对：

1. **原话**：需求基线里的原话必须与用户消息**逐字一致**（当前会话由 AI 传入后插件逐字比对；跨会话由插件从会话日志取回）；
2. **路径**：详情里写的文件路径必须在磁盘上真实存在，否则**拒绝写入**；
3. **变更**：每次状态/内容变更都追加一条带会话、时间、轮次、说明的追溯记录。

任何一个环节取不到，宁可标「待锁/待确认」并让它可见，也不静默补一个“差不多”的值。

### 2.3 不静默降级

所有降级路径必须可见：原话取不到显示「原话待锁」；宿主不支持文件打开时复制路径并提示；宿主版本过旧时显示「旧版宿主，重启后可用」；锚点检测失败时给出明确提示。**不把失败包装成成功。**

### 2.4 人与 AI 双写者分离

每个文件只有一个写者：

- `<id>.md`（AI 详情）只由工具写；
- `<id>.note.md`（用户备注）只由面板写；
- 面板与工具都不碰对方的文件。

好处是并发安全、责任清晰：AI 改不坏你的备注，你也不会覆盖 AI 的详情。

### 2.5 数据在本地、按工作区隔离

所有数据落在 `<DSH_HOME>/storages/compass/<工作区名>-<hash>/`，一个会话只对应一个工作区，无网络上报。
**没有“切换工作区”功能**：面板永远显示当前会话的工作区；其它任务板数据只在设置页做磁盘清理（见 §9）。

### 2.6 承认会话是真源码，退出历史舞台的功能要敢删

- **全局时间线与变更流**已移除：单任务的追溯链已经覆盖“刚才改了什么”，一个全局流水账只增加噪音。
- **多工作区并行看板**已移除：隔离工作区下切换看板会让面板与 AI 工具作用域不一致，属于过度设计。
- **设置页不是看板切换器**：它只是本机任务板数据的磁盘清理工具。

### 2.7 契约先行（对开发者）

实现与文档不一致时：**先改契约，再改代码**。数据格式、状态语义、UI 行为以文档为准；新能力要先在文档里定清楚，再落地。

## 3. 任务板怎么用

打开任意会话的右侧边栏 →「任务板」卡片。

- **三视图**：只看当前（默认）/ 只看在动 / 完整轨迹。
- **需求行**：显示子任务机械计数（如 `12 条任务 · 进行中 2 · 已阻塞 1`）。
- **钉顶区**：待裁决 / 冲突的节点跨层级置顶，一眼看到需要你拍板的事。
- **详情弹窗**：左边 AI 详情（只读）、右边你的备注（自动保存）；下方追溯链与文件锚点。
- **搜索**：视图内过滤，命中节点自动展开祖先链。
- **复制交接**：详情底部一键复制「任务 id / 路径 / 双线状态 / 追溯链 / 需求明面 / 详情 / 备注」。
- **刷新**：面板每 2 秒自动轮询；编辑备注期间不打断；有更新时可手动刷新。
- **主题与宽度**：明暗跟随宿主；面板窄到 340px 仍不横向滚动（长文本省略/换行）。

### 交接流程（用户 SOP）

1. 在任务板找到要交接的节点 → 详情 →「复制交接内容」；
2. 新会话首条消息粘贴；
3. 新会话 AI 用 `compass_read` 读板核实后继续，必要时用工具更新状态。

插件**不会**自动向会话注入上下文——是否交接、交接哪条，由你决定。

## 4. 双线状态与状态机

每个节点（需求/任务）有**两条互相独立的状态线**：

### 4.1 执行线

| 状态 | 含义 | 谁来判断 |
|---|---|---|
| 未开始 | 还没动 | AI |
| 进行中 | 正在做 | AI |
| **已阻塞** | 等第三方 / 等确认 / 被卡住，需要人介入 | AI |
| 已执行 | 做完了 | AI |

### 4.2 裁决线

| 状态 | 含义 |
|---|---|
| （空） | 无裁决问题 |
| 待裁决 | 需要用户拍板（与旧需求撞车、范围变化等） |
| 冲突 | 两个需求/会话互相矛盾，尚未定论 |
| 已废弃 | 该节点作废（必须写原因） |
| 已替代 | 被其它节点替代（必须写原因） |

### 4.3 转移规则（用户视角）

- 执行线四态之间**可自由互转**（AI 判断），每次变更必须带一句 `pointer_note` 说明。
- 裁决线**不能凭空废弃**：必须 `待裁决/冲突 → 已废弃/已替代`，并写 `dead_reason`；这是为了让“为什么废”有据可查。
- 废弃/替代父节点时，必须**覆盖整棵子树**（或明确说明哪几条不废），防止留下悬空子任务。
- 「已确认继续」是瞬时值：AI 传它表示“用户已确认继续”，落盘时自动归零为“无裁决”。

### 4.4 需求层状态由插件机械聚合

需求行的 `exec_state` 不再是 AI 写的，而是插件按子任务**机械聚合**的派生值：全已执行→已执行；任一已阻塞→已阻塞；任一进行中或混合→进行中；全未开始→未开始（忽略已废弃/已替代子树）。AI 手写需求状态会被拒绝——它只需要更新子任务，需求行自动重算。这样“状态”永远是事实的汇总，不会漂移。

### 4.5 钉顶与显示主导权

- **待裁决 / 冲突**在任何视图都可见，并进入钉顶区；
- **已废弃 / 已替代**只在「完整轨迹」出现；
- 执行线与裁决线冲突时，**裁决线决定可见性**：被判废弃的任务不会因为“已执行”而重新出现在默认视图。

## 5. 追溯链与证据

每次建节点、改状态、改裁决、合并、移动、写备注（备注只记录“已更新”，不存内容）都会追加一条追溯记录：

```json
{ "session": "<会话 id>", "at": "<ISO 时间>", "turn": 12, "note": "为什么做这次变更" }
```

- `session` / `at` 由插件自动填，AI 不能编造；
- `turn` 优先由宿主 `turn/start` 事件追踪；插件在轮次中途加载时，用**当前会话日志**还原当前轮（同一编号体系）；都取不到就留空（**不猜**——不再用「用户消息条数」估计，那种近似会把第 3 轮记成第 38 轮）；
- `note` 是 AI 写的一句话理由。

详情里的追溯链支持**跳回原会话**、**定位到第 N 轮并高亮**。这是事后复盘“当时为什么这么定”的证据链。

**跳转不靠信仰，靠核验**：点击前，插件先用会话日志核对这个「第 N 轮」是否真实存在；旧版本写错轮次的历史数据，会按追溯记录的时间（`at`，权威）还原到真实轮次；来自**子代理会话**的记录不能直接打开，会跳到**父会话**里对应时刻的那一轮。会话列表里看不到的历史会话，也按会话日志核验存在性，不再误报「会话不可用」；核验不了就明确说原因（日志缺失 / 轮次不存在 / 没渲染出来），不假装定位成功。

### 跨会话撞车警示

当一条任务同时满足：**执行态是进行中/已阻塞** + **非终态裁决** + **最近 30 分钟内有其它会话的追溯记录** 时，行上出现一个极小的幽灵标，提示“另一个会话正在动它”。历史变更不报警，避免满屏红灯。

## 6. 原话基线：为什么必须逐字

每个需求在基线里存两样东西：

- **明面（surface）**：AI 精简的一句话，给人看；
- **原话（original）**：用户当初说的**逐字原文**，给核对用。

原话的写入方式（v1.24 起）：

| 场景 | 谁提供 | 插件做什么 |
|---|---|---|
| 当前会话、刚刚听到 | AI 通过 `original_text` 传入 | 与当前会话用户消息**逐字比对**，一致才锁定；不一致直接拒绝（`E_ORIGINAL_MISMATCH`） |
| 跨会话、历史回填 | 插件按 `refs` 从会话日志取回 | AI 不传正文；插件逐字读出并剥掉机器注入块 |
| 取不到 | — | 记「原话待锁」，在 UI 让用户粘贴后锁定（兜底，不静默） |

> **为什么不让 AI 直接写？** 因为 AI 会“顺手优化”一句话，而原话失真是事后无法发现的。当前会话的放宽点是“AI 可以传，但必须逐字且由插件校验”——既省一次历史扫描，又不放弃保真。

运行时快照（`Time sampled while preparing turn…`、`Browser time zone for this request:` 等）属于机器注入内容，**永远不会**被当成用户原话。

需求变更用 `compass_change` **追加版本**，不覆盖旧版；每一版都重新锁定该版原话。

## 7. 路径事实：锚点与写入强校验

### 7.1 文件锚点（读侧）

详情和备注里出现的文件路径会被机械识别成可点击锚点。打开详情时，插件先做一次**存在性检测**：

- **存在** → 蓝色可点，打开 DSH 文件预览；
- **不存在** → 灰色虚线弱化，点击 = 复制路径 + 提示「路径不存在，已复制」，**不会**再弹出“文件不存在”；
- **检测失败**（旧宿主缺接口）→ 保持可点并提示「无法检测（宿主版本过旧）」。

### 7.2 写入强校验（写侧，根治幻觉）

`compass_plan` / `compass_update` 写详情前，会用 `fs.existsSync()` 检查详情里识别出的**所有**文件路径；**任一不存在 ⇒ 整次写入拒绝**：

```text
[Error] 详情写入被拒绝。
原因：检测到详情内容中包含不存在的文件路径 "src/api/user.ts"。
建议操作：请使用终端命令或文件工具核实当前工作区的真实文件结构，并使用真实的绝对路径或相对路径重新提交。严禁捏造路径。
```

被拒时任务树、状态、追溯链、详情**都不会变**。AI 收到错误后应去查真实目录并重写，而不是换个入口绕过。

**两个使用约定**：

1. 跨仓库引用请写**绝对路径**（相对路径会按当前工作区解析）；
2. 还没创建的文件不要写成锚点（反引号路径）——用普通文字描述“计划新增…”。这是“不许说谎”的代价。

**豁免**：`compass_import`（导入别的工作区数据）与 `compass_migrate`（迁移历史文档原文）不校验——它们不是 AI 现编的当前事实。

## 8. 生命周期与数据管理

- 每个工作区一份数据目录：`<DSH_HOME>/storages/compass/<工作区名>-<hash>/`；
- 项目被删/移动后，数据仍在（标「路径已失效」），不会自动删除；
- **设置页 → 本机任务板数据**：列出本机全部数据（名称/路径/节点数/更新时间/状态），失效项可手动「清理」（只删数据目录，不动原项目），当前数据也可删（删后任务板变空）；
- **迁移与备份**：导出为 JSON bundle（树 + 详情 + 备注 + 基线原文），可在另一个工作区导入（目标板必须为空）；
- **一键卸载**：移除 `<DSH_HOME>/AGENTS.md` 规则区块 + 删除全部工作区数据（强二次确认；规则区块损坏时中止，不删数据）。

## 9. AI 如何维护任务板（规则层）

插件在 `<DSH_HOME>/AGENTS.md` 里安装一个标记区块（`compass_init` 安装/幂等升级），新会话生效。规则要点：

1. **开工先规划**：用户确认开工后，先建完整任务树（含未开始），执行中逐步推进状态；
2. **层级按从属组织**：子任务挂到对应父任务下，验收/优化项挂对应验收任务，不要全平铺在需求层；
3. **详情按交接文档写**：必须有「核心文件 / 契约文档 / 避坑指南」三段锚点（每段各起一行、标签在行首；没有写“无”）；
4. **阻塞要有写法**：标「已阻塞」，第一行写「阻塞：等什么 / 谁能解 / 下一步」；
5. **父链一起更新（硬校验）**：写任何详情（含完成说明）必须同批更新**整条祖先链**（父任务、父级的父级、需求）的汇总，缺一个就拒绝（`E_ANCESTOR_DETAIL_REQUIRED`）；需求将被聚合为「已执行」前，必须先有需求完成汇总（`E_REQUIREMENT_DETAIL_REQUIRED`）。插件只做机械校验与陈旧检测（`health.stale_chains`），不替 AI 写汇总；
6. **history 边界**：历史会话扫描（`compass_import`）只用于「新会话且交接不足需溯源」与「跨会话修复/审计（先说明）」；当前上下文已有的原话/诉求不得再拉历史；
7. **每轮自查**：先 `compass_status`，做了改变板面的事就落板，确认没变才忽略；
8. **标记已执行必须留完成说明**：单节点用 `detail`，批量用 `details`（逐任务）；修改/构建型写「核心文件 / 契约 / 避坑指南」（路径必须真实存在），查询/调研型写「查询结论 / 数据来源 / 后续建议」（可无路径）。三段必须各起一行、标签在行首、段内容非空——插件按结构校验，一句话糊过三段标签会被拒绝。
9. **同题任务必须闭环**：`compass_plan` / `compass_require` / `compass_update` 返回疑似重复警告、或 `compass_status` 的 `health.duplicate_pairs` 命中时，先确认是否同一问题；同一问题把旧任务标「已替代」并在 `dead_reason` 写清被谁取代，**不要留同题未开始任务**（插件只做机械查重提示，判断权仍在 AI/用户）。
10. **按 health 自查存量**：`health.missing_detail`（已执行但没详情）、`health.stale_chains`（子节点详情比祖先新）是机械事实，不是建议——发现就补写/同步，别让它一直红着。

## 10. 防膨胀

任务板最大的风险不是功能少，而是**越用越大、越用越慢、越看越乱**。四层机制：

1. **树要小**：`tree.json` 只存层级、状态、追溯链、合并/废弃信息；详情、备注、基线原文全部拆到独立文件，打开面板一次只读小树。
2. **详情按需**：`details/` 里的内容只有点开详情或 AI 调 `compass_read(detail:<id>)` 时才读，不把整个工作区的详情塞进 AI 上下文。
3. **显示降噪**：默认「只看当前」视图隐藏已废弃/已替代；“待裁决/冲突”才钉顶；空态、搜索、折叠都为了少看噪音。
4. **规则约束**：AI 按 `AGENTS.md` 规则写「人话」而不是流水账；详情按交接文档三段锚点写，不接受“贴一大堆日志”。

插件不做自动摘要（那是 AI 的判断），也不做“压缩历史”——需要归档时由用户决定导出或清理。

## 11. 边界与非目标

- 不判断完成度、覆盖关系、冲突真伪——判断权归 AI/用户；
- 不做每轮提醒、不自动向会话注入上下文；
- 不做实时多人协同、不做 diff 合并（备注以最后写入者为准）；
- 不做全局时间线、不做工作区看板切换、不做拖拽排序、不做删除任务；
- 不生成语义摘要（“一句话人话”由 AI 写）；
- 不做云端同步：数据只在本地 `<DSH_HOME>`。

---

## 12. 已知限制

- **平台**：需要 DSH 宿主（工具注册、右侧栏 tab、webServer 路由），独立 Node 进程跑不了 UI；
- **路径识别**：要求扩展名白名单且不含空格/中文（如 `某 技术方案 v1.2.md` 会被截断识别）；
- **Windows 优先**：路径规范化与文件打开按 Windows 语义实现（POSIX 也可运行，但未做全平台回归）；
- **任务质量取决于 AI**：插件只做机械校验，AI 不按规则维护时，板面会陈旧（`compass_status` 能机械提示“板面 N 轮未落板”）；
- **旧宿主**：升级插件后需要重启 DSH 才能加载新的宿主侧逻辑（面板会提示“旧版宿主”而不是报错）；
- **轮次可缺省**：追溯跳转依赖会话日志（`<DSH_HOME>/sessions`）；会话没有持久化日志时只能打开原会话、核验不了轮次，会明确提示而不是编一个轮次；
- **祖先链校验的范围**：硬校验作用于「写详情 / 标记已执行」；纯状态推进（未开始 → 进行中）不阻断，父链是否陈旧由 `compass_status.health.stale_chains` 机械暴露；`compass_migrate` 与整板恢复豁免；
- **子代理会话**：子代理的会话记录不能像主会话那样在聊天区打开，追溯只能跳到父会话的对应轮次。

## 13. 核心术语表（Glossary）

| 术语 | 大白话 |
|---|---|
| **任务板** | 右侧栏里那棵树：需求 → 任务 → 步骤，带状态和详情。 |
| **需求树** | 按“用户要什么 → 拆成哪些任务 → 每个任务怎么做”组织的层级结构。 |
| **双线状态** | 一条任务同时有两个状态：**做得怎么样**（执行线）和**要不要你拍板**（裁决线），互不覆盖。 |
| **执行线** | 未开始 / 进行中 / 已阻塞 / 已执行——AI 判断进度用。 |
| **裁决线** | 空 / 待裁决 / 冲突 / 已废弃 / 已替代——需要用户决定或已作废的记录。 |
| **已阻塞** | 不是“慢”，是“卡住了等外部条件”，需要人介入；面板黄色高亮并计数。 |
| **待裁决 / 冲突** | 需要你拍板的事；两者都会钉在面板顶部，任何视图都看得到。 |
| **钉顶** | 把待裁决/冲突节点固定显示在列表顶部，不管它原本在第几层。 |
| **追溯链** | 一条任务的历史变更记录（谁、在哪个会话、第几轮、为什么改），可点回原会话。 |
| **原话基线** | 需求最初那句用户原话，逐字保存、不可改写；每版变更都追加，不覆盖。 |
| **明面** | AI 把原话精简成的一句话，给人快速读；和原话一起存。 |
| **逐字校验** | 原话必须和会话里用户发的内容一个字不差，多一个标点都拒绝。 |
| **交接内容** | 一键复制的任务摘要（状态、路径、追溯链、详情、备注），粘贴给新会话 AI 接手。 |
| **撞车警示** | 任务最近 30 分钟被另一个会话动过时，行上的小幽灵标；历史变更不报警。 |
| **文件锚点** | 详情里被识别成可点击的路径标签；点开能在侧边栏预览文件。 |
| **三态锚点** | 锚点的三种显示：存在（可点）/ 不存在（弱化，点击复制）/ 检测失败（提示旧宿主）。 |
| **锚点校验（写入强校验）** | 写详情前检查里面每个文件路径是否真实存在，不存在就拒绝写入——防止 AI 编造路径。 |
| **写锁 / 乐观版本校验** | 两个窗口同时写同一份数据时的保护：排队写、写前对版本，避免互相覆盖。 |
| **工作区数据目录** | 每个项目一份任务板数据，存在 `<DSH_HOME>/storages/compass/` 下，按路径 hash 区分。 |
| **孤儿数据 / 路径已失效** | 项目目录被删/移动后，任务板数据还在；面板标出来，让你决定要不要清理。 |
| **规则区块** | 插件写进 `<DSH_HOME>/AGENTS.md` 的一段规则，教 AI 怎么维护任务板；可用 `compass_init` 重装/升级。 |
| **可见降级** | 出问题时明确告诉你哪里不行、怎么处理，而不是假装成功。 |
| **schema** | 数据格式的版本号；升级插件时按它做兼容迁移（当前 `schema = 2`）。 |
| **完成说明** | 标「已执行」时必须留的交接说明：修改型写核心文件/契约/避坑指南，调研型写查询结论/数据来源/后续建议。 |
| **需求完成汇总** | 需求被机械聚合为「已执行」前必须写好的三段：验收范围 / 完成结论 / 遗留风险。 |
| **祖先链汇总** | 写任何详情时，父任务、父级的父级、需求必须同步更新的三段汇总（缺一拒绝）。 |
| **父链陈旧（stale chain）** | 子节点详情比祖先新、说明父链没跟随的机械事实；`compass_status.health` 会列出。 |
| **子代理会话** | 子任务/子代理的会话（裸 UUID）；追溯可跳它所属父会话的对应轮次，不能在聊天区直接打开。 |
